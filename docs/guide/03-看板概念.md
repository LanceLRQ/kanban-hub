# 看板的概念

kanban-hub 的看板分三层：项目下面是容器，容器下面是任务。另外每个项目有一条事件时间线，记录谁在什么时候改了什么。

## 项目

一个项目对应一个代码仓库。同一个仓库在几台机器上都有副本时，它们属于同一个项目，每台机器上的路径记为项目的一个“位置”。

项目有三个 AI 和你都会经常改的字段：

| 字段 | 取值 |
|---|---|
| 周期 | 设计期 `design`、开发期 `development`、迭代期 `iteration`、维护期 `maintenance`、归档 `archived` |
| 健康度 | 正常 `on_track`、有风险 `at_risk`、卡住 `blocked` |
| 当前焦点 | 一句话，说明眼下在做什么 |

项目最近一条事件距今超过 7 天（`KH_STALE_DAYS` 可调），并且没有归档，项目卡片上会出现“停滞”标记。

## 容器

容器是任务的分组，有三种：

- 阶段 `phase`：开发期常用，比如 M0、M1、M2，一个接一个推进。
- 特性 `feature`：迭代期常用，几个特性可以同时进行。
- 杂项 `misc`：每个项目自动有一个，不能删除，用来放零散的事情，以及干活时顺手发现、暂时不处理的问题。

容器可以有编号（`P0`、`M3a`）、目标版本（`v1.1`）和目标日期。

容器的状态一般不用手动设置，按里面的任务自动推算，规则按顺序判断：

1. 设置了手动状态，就用手动状态。可选的手动状态有储备、挂起（必须写原因）、已取消。
2. 不算已取消的任务，剩下没有任务或者全是待开始，就是“待开始”。
3. 不算已取消的任务，剩下的全部已完成，就是“已完成”。
4. 其他情况都是“进行中”。

杂项容器不推算状态，只显示还有几个任务没做完。

“储备”适合放想做但还没排上日程的阶段或特性。看板上它们单独排在一块，不会和进行中的混在一起。

## 任务

| 字段 | 说明 |
|---|---|
| 状态 | 待开始 ⬜、进行中 🔶、复核中 👀、已完成 ✅、挂起 ⏸（必须写原因）、已取消 |
| 待你处理 | 需要人介入的标记，分待决策、待验证、待操作三种，附一句说明 |
| 编号 | 可选，比如 `2.3` |
| 分组 | 可选的标签，比如特性内部再分 `M2`、`安全` |
| 备注 | 一句话 |
| 关联文档 | 仓库内的相对路径，网页上可以点开 |
| 清单 | 若干勾选项，单独计算完成度 |
| 截止日期 | 可选 |

状态之间可以任意切换，不受顺序限制，这样 AI 改错了也能直接改回来。开始日期和完成日期自动记录：

- 第一次变成进行中时记下开始日期，以后重新打开也不会覆盖。
- 变成已完成时记下完成日期；从已完成改回别的状态，完成日期清空。

任务没有删除操作。不做了就标成已取消，它不计入进度，在看板上会被划掉。

### 待你处理

这是 kanban-hub 最值得留意的标记。AI 在工作中遇到需要你拍板的问题、需要你亲手验证的结果、或者只有你能做的操作（比如配置密钥），会在任务上打这个标记。首页把所有项目里带标记的任务汇总在一起，按三种类型分组，打开网页先看这里就够了。

处理完之后，在网页的任务侧边栏里清除标记，或者让 AI 执行 `kh task human <任务> --clear`。

## 进度

进度 = 已完成数 ÷（总数 − 已取消数）。

- 容器的进度按容器内的任务计算。
- 项目的进度只统计阶段和特性里的任务，不含杂项。杂项里的零碎事情很多，算进去会让进度失真。
- 清单的完成度与任务状态分开计算，不影响进度。

## 时间线

每次修改都会记一条事件，时间线里能看到：项目和容器的改动、任务的新建与状态变化、待你处理标记的变化、AI 用 `kh log` 写的日志、文档同步和拉取、导入。

每条事件记着操作者：哪个用户、哪台机器、来自网页还是命令行，以及是哪个 agent。`kh` 会从环境变量识别 Claude Code、Codex、Gemini CLI、OpenCode，识别不出来时为空，也可以用 `--agent <名称>` 显式指定。

## 网页和 AI 同时修改怎么办

网页上的修改带版本号。你在网页上编辑时，如果 AI 刚好改了同一个任务，保存会失败并提示“数据已被更新”，页面随即刷新，你再改一次就好。

`kh` 的请求不带版本号，后写入的生效。被覆盖的修改在时间线里都查得到。
