# kh 命令参考

`kh` 主要由 AI 调用，你自己偶尔也会用到。任何命令加 `--help` 都能看到完整的参数说明。

除了 `login`、`logout`、`whoami`、`setup`、`backup`，其他命令都要在已注册的仓库里执行，`kh` 会从当前目录往上找到仓库根目录，读取 `.kanban-hub/config.yaml` 确定项目。

## 怎么指定容器和任务

容器可以写：

- 编号，比如 `M2`
- `misc`，表示杂项容器
- ID 前缀

任务可以写：

- `容器编号/任务编号`，比如 `M2/2.3`
- `#` 加短 ID，比如 `#k3v9`。短 ID 在 `kh status` 的输出里能看到，是能区分各任务的最短前缀，至少 4 位。在 shell 里要加引号写成 `"#k3v9"`，否则 `#` 之后的内容会被当成注释丢掉
- 完整 ID

可以清空的字段，传空字符串就是清空，例如 `--code ""`、`--due ""`。

所有命令都接受 `--agent <名称>`，用来标明调用者是哪个 agent，会记进时间线。不传时 `kh` 会从环境变量自动识别。

## 接入

| 命令 | 作用 |
|---|---|
| `kh login --server <地址> --code <配对码> [--name <机器名>]` | 用配对码登录，保存本机令牌 |
| `kh logout` | 删除本机令牌，服务端地址保留 |
| `kh whoami` | 显示当前登录的服务端和机器 |
| `kh setup [--dry-run] [--yes] [--uninstall]` | 安装或卸载 skill 与 Claude Code hook，见《接入》 |

## 项目

| 命令 | 作用 |
|---|---|
| `kh register [--name <名称>] [--bind <项目ID> \| --new] [--include <glob>]… [--dry-run] [--yes]` | 注册当前仓库，见《接入》 |
| `kh status [--json]` | 显示项目进度：周期、健康度、焦点、各容器和任务 |
| `kh project set [--cycle <周期>] [--health <健康度>] [--focus "<焦点>"]` | 修改项目字段，至少给一项 |

```bash
kh project set --cycle iteration --health at_risk --focus "修复支付回调超时"
```

## 容器

| 命令 | 作用 |
|---|---|
| `kh container add <phase\|feature> "<标题>" [--code <编号>] [--version <版本>] [--target-date <日期>]` | 新建阶段或特性 |
| `kh container set <容器> [--status <状态>] [--reason "<原因>"] [--title …] [--code …] [--version …] [--target-date …]` | 修改容器 |
| `kh container reorder <容器…>` | 调整阶段、特性容器之间的先后顺序 |

`--status` 可选 `backlog`（储备）、`suspended`（挂起，必须带 `--reason`）、`cancelled`（已取消）、`auto`（去掉手动状态，恢复自动推算）。

```bash
kh container add phase "用户系统" --code M2 --target-date 2026-10-15
kh container set M2 --status suspended --reason "等第三方短信接口开通"
kh container set M2 --status auto
kh container reorder M3 M2 F1
```

`container reorder` 是部分列表：列出的容器按给定顺序排在最前，没列出的保持原有相对顺序跟在后面。杂项容器固定在最后，不参与重排，不能写在参数里。网页把容器分成正常、储备两组，顺序只在所属分组内起作用。

## 任务

| 命令 | 作用 |
|---|---|
| `kh task add <容器> "<标题>" [--code <编号>] [--group <标签>] [--doc <路径>]… [--due <日期>]` | 新建任务 |
| `kh task set <任务> [--status <状态>] [--reason …] [--note …] [--doc <路径>]… [--title …] [--code …] [--group …] [--due …] [--container <容器>]` | 修改任务 |
| `kh task human <任务> (--decision \| --verify \| --action) "<说明>"` | 打上“待你处理”标记 |
| `kh task human <任务> --clear` | 清除“待你处理”标记 |
| `kh task checklist <任务> --add "<内容>"`… | 追加清单项，`--add` 可以写多个 |
| `kh task check <任务> <序号> [--undo]` | 勾选清单项，序号从 1 开始；`--undo` 取消勾选 |
| `kh task reorder <容器> <任务…>` | 调整一个容器内任务的先后顺序 |

任务状态：`todo`、`in_progress`、`review`、`done`、`suspended`（必须带 `--reason`）、`cancelled`。

`task set --doc` 是追加关联文档，不是替换，重复的路径会自动去重。`--container` 把任务移到另一个容器。

```bash
kh task add M2 "邮箱验证码登录" --code 2.3 --doc docs/login.md
kh task set M2/2.3 --status in_progress
kh task set "#k3v9" --status review --note "等你在手机上试一遍"
kh task human "#k3v9" --verify "用真实邮箱走一遍注册流程"
kh task add misc "登录页在窄屏下按钮错位"
kh task reorder M2 2.3 "#k3v9"
```

`task reorder` 同样是部分列表：列出的任务排在最前，没列出的保持原有相对顺序跟在后面。任务可以写本容器内的编号（如 `2.3`）、`#` 加短 ID 或 `容器编号/任务编号`，必须属于该容器，杂项容器写 `misc`。

重排前先用 `kh status` 看当前顺序。顺序没有变化时不写入，命令输出“顺序未变化”。重排不改变任务状态，也不算一次进度上报。

## 时间线

```bash
kh log "完成邮箱验证码登录，测试全部通过"
```

## 文档同步

| 命令 | 作用 |
|---|---|
| `kh sync [--quiet]` | 把本机同步范围内的文档推送到服务端 |
| `kh docs ls [--from <机器>] [<glob>]` | 列出其他机器快照里的文件 |
| `kh docs cat [--from <机器>] <路径>` | 把另一台机器上的文档打印到标准输出，不写本地文件 |
| `kh pull [--from <机器>] [--path <glob>] [--dry-run]` | 把其他机器的文档拉到本地 |
| `kh conflicts` | 列出未解决的冲突 |
| `kh conflicts show <路径>` | 查看冲突的差异 |
| `kh conflicts resolve <路径> (--edited \| --take-local \| --take-remote)` | 标记冲突已解决 |

`--from` 写机器名或机器 ID 前缀。各条规则的细节见《文档同步与冲突》。

## 导入导出

| 命令 | 作用 |
|---|---|
| `kh import <文件> [--dry-run]` | 把 YAML 文件导入当前项目 |
| `kh export [--md] [-o <文件>]` | 导出看板，默认 YAML，`--md` 导出 Markdown；不带 `-o` 时输出到标准输出 |

格式说明见《导入导出》。

## 备份

```bash
kh backup                # 交互输入两遍密码，直接回车表示不加密
kh backup --no-history   # 不含数据目录的 git 历史，文件更小
```

服务端创建备份后，`kh` 会把它下载到当前目录。备份文件同时留在服务端的 `backups/` 目录里。

密码只能在终端里交互输入，没有命令行参数，避免密码留在 shell 历史里。

## 本机文件

```
~/.kanban-hub/
├── config.yaml     # 服务端地址、本机 ID 与名称
├── credentials     # 本机令牌，权限 600
├── cache/          # 文件 hash 缓存、拉取用的基准内容、冲突、会话标记
├── imports/        # AI 写的导入文件
└── logs/hook.log   # hook 的日志，超过 1MB 时轮换一次
```

用环境变量 `KH_HOME` 可以换一个目录（必须是绝对路径）。

## 退出码

| 退出码 | 含义 | 怎么办 |
|---|---|---|
| 0 | 成功 | |
| 1 | 意外错误，比如服务端内部错误 | 看错误信息和服务端日志 |
| 2 | 用法错误，参数不对 | 加 `--help` 查看用法 |
| 3 | 未登录、令牌失效或已吊销、配对码无效、请求太频繁 | 到网页 `/setup` 重新生成配对码，执行 `kh login` |
| 4 | 连不上服务端 | 检查地址、网络和服务是否在运行 |
| 5 | 数据校验失败或版本冲突 | 按错误信息里的字段路径修正 |
| 6 | 与服务端版本不兼容 | 用 `npm i -g <服务端地址>/setup/kh.tgz` 重新安装 |
