# 导入导出

导入导出用同一种 YAML 格式。常见用途有三个：

- 迁移：仓库里原来有 `TASKS.md` 之类的进度文档，让 AI 整理成导入文件，一次性导进看板。接入引导里的 `migrate.md` 走的就是这条路。
- 批量编辑：导出、修改、再导入。
- 把进度快照放进仓库：用 `kh export --md` 导出成 Markdown。

## 导入

```bash
kh import ~/.kanban-hub/imports/my-app.yaml --dry-run   # 先预览
kh import ~/.kanban-hub/imports/my-app.yaml
```

`kh` 会先在本地校验文件，出错时指出字段路径，比如 `containers[1].tasks[3].status`。校验通过后才发给服务端。`--dry-run` 列出将要新建、更新的条目和状态变化，不写入任何数据。

导入可以重复执行，已经导入过的条目会被匹配上，不会重复新建。

## 格式

```yaml
format: kanban-hub/v1
project:                  # 可选，只能写这三个字段
  cycle: development
  health: on_track
  focus: "上线用户系统"
containers:               # 必填，可以是空数组
  - kind: phase           # phase / feature / misc，misc 最多一个
    code: "M2"
    title: 用户系统
    targetVersion: "v0.1"
    targetDate: 2026-10-01
    manualStatus: backlog # 可选：backlog / suspended / cancelled
    tasks:
      - code: "2.1"
        title: 注册与登录接口
        status: done
        group: "后端"
        note: "密码用 argon2 哈希"
        docRefs: [docs/login.md]
        checklist:
          - { text: "注册", done: true }
          - { text: "登录", done: true }
        dueDate: 2026-08-15
        startedAt: 2026-08-10T10:00:00+08:00
        completedAt: 2026-08-14T18:00:00+08:00
      - code: "2.2"
        title: 短信验证码
        status: suspended
        suspendReason: "等第三方短信接口开通"
        human: { kind: decision, note: "选哪家短信服务商" }
  - kind: misc
    tasks:
      - title: 登录页在窄屏下按钮错位
        status: todo
events:                   # 可选，历史日志
  - ts: 2026-08-14T18:00:00+08:00
    text: 完成注册与登录接口
```

各字段的取值与看板一致，见《看板的概念》。几条容易出错的规则：

- 编号、标题、版本、分组、备注这类文本字段，如果 YAML 会把它解析成数字或布尔值，一定要加引号。YAML 会把 `2.3` 当成数字，把 `1.10` 变成 `1.1`，把 `targetVersion: 1.0` 变成 `1`。`kh` 遇到这种情况会报错，不会悄悄转换。
- 时间必须带时区，比如 `+08:00`。日期写 `YYYY-MM-DD`。
- 挂起的容器和任务必须写原因（`manualReason`、`suspendReason`）。
- 只有已完成的任务才能写 `completedAt`。
- 杂项容器不能设置手动状态，`title` 可以省略。
- 所有对象都不接受未知字段，拼错字段名会报错。
- 文件按 YAML 1.2 解析，不接受 `%YAML 1.1` 指令。
- 文件里不写负责人。

## 重复导入时怎么匹配

- 容器按“类型 + 编号”匹配，编号不区分大小写。没写编号时，按“类型 + 标题”匹配。杂项容器直接对应项目自己的杂项容器。
- 任务只在所属容器里匹配，规则同上：先看编号，没有编号看标题。
- 文件里带编号、看板上同名条目没有编号时，也能匹配上，并把编号补给它。所以先在网页上建了没编号的阶段，再导入带编号的同名阶段，不会重复。
- 匹配上的条目只更新文件里写了的字段。可以清空的字段写 `null` 表示清空。
- 文件里没有的已有条目保持不动。导入不会删除任何东西。
- 任务换了容器，会在新容器里新建一个，旧的不动。
- 新建的容器和任务排在末尾，按文件里的顺序。已有容器的顺序不变。
- 状态变了，开始和完成日期按常规规则推算；文件里写了 `startedAt`、`completedAt` 的，以文件为准。
- 历史日志按“时间 + 正文”去重，已经存在的不会再写一遍。

一次导入只在时间线上记一条“应用了一次导入”，带上各类计数。完全没有变化时什么都不记。

## 导出

```bash
kh export                       # YAML，输出到标准输出
kh export -o board.yaml         # 写到文件，父目录必须已存在
kh export --md -o docs/PROGRESS.md
```

网页的项目设置页也能下载这两种格式。

YAML 导出包含全部容器（含杂项）、任务和项目的全部日志。同一份导出导回同一个项目，不会产生任何变化；导进一个新项目，会得到一个等价的看板。

Markdown 导出适合放进仓库给人看：项目名、周期、健康度、进度、焦点、导出时间，每个容器一节，任务一行一个，已取消的任务划掉。里面不含 `#` 短 ID，因为短 ID 会随着任务增加而变长。
