# 常见问题

## 接入

### 配对码提示无效

配对码 10 分钟过期，只能用一次，而且只存在服务端内存里，服务重启后也会失效。回到 `/setup` 重新生成一个。

连续输错会被限流：同一个 IP 每分钟最多失败 5 次。等一分钟再试。

### `kh` 报退出码 6，版本不兼容

服务端升级后，开发机上的 `kh` 也要跟着升级：

```bash
npm i -g http://<服务端地址>/setup/kh.tgz
```

装完后再执行 `kh setup --yes` 更新 skill 与 hook。完整步骤和可以直接发给 AI 的提示词见[接入：升级 kh 与 skill](02-接入.md#升级-kh-与-skill)。

### 忘了管理员密码

密码只来自环境变量 `KH_ADMIN_PASSWORD`。改掉 `.env` 里的值，重启服务（一键脚本用 `bash kanban-hub.sh config` 修改），新密码即刻生效。所有网页会话会失效，已接入机器的令牌不受影响。

## Claude Code hook

### hook 好像没有生效

按顺序检查：

1. 执行过 `kh setup --yes` 之后，要新开一个 Claude Code 会话，hook 才会加载。
2. 仓库根目录要有 `.kanban-hub/`。没注册的仓库，hook 什么都不做，连日志都不写。
3. 本机要已经登录。执行 `kh whoami` 确认。
4. Claude Code 要能找到 `kh`。从图形界面（比如桌面应用、IDE）启动的 Claude Code，PATH 可能和终端里不一样，尤其是用 nvm、fnm 这类工具装的 Node。让 Claude Code 执行一下 `kh --version`，如果找不到，或者版本号和终端里的不一样，就需要调整 PATH，或者把 `~/.claude/settings.json` 里的 `kh` 改成绝对路径。
5. 看日志：`~/.kanban-hub/logs/hook.log`。hook 出任何错都不会打断会话，错误只写在这里。

### 每轮回复结束都被提醒上报

不会的。Stop hook 每个会话最多提醒一次，而且只在同时满足这些条件时提醒：这次会话改过仓库（有新提交或者未提交的改动有变化），并且会话开始以来这台机器没有上报过任何进度。

只改了被 git 忽略的文件（比如私有文档目录），不算改过仓库，不会提醒。

### 会话开头的进度摘要没出现

服务端连不上时，摘要完全不输出，原因写在 `hook.log` 里。摘要要在 15 秒的 hook 超时内生成完，网络很慢时也可能来不及。

### 在 git worktree 里工作

`.kanban-hub/` 默认被本地排除，链接工作树里没有这个目录。hook 会沿用主工作树的注册配置：拉取和推送的是主工作树那边的文档，判断“有没有改动”看的是你当前所在的工作树。

## 网页

### 保存时提示“数据已被更新”

你编辑的同时，AI 或另一个标签页改了同一条数据。页面会自动刷新，重新改一次即可。

### 网页上的操作都提示失败，但能正常浏览

多半是同源校验没通过。服务部署在反向代理后面，代理改写了 Host 头时会出现这种情况。在 `.env` 里把 `KH_PUBLIC_URL` 设成浏览器里访问的地址，或者让代理保留原始 Host。

### 开了很多标签页之后，页面加载卡住

每个可见的标签页占一条实时连接。直接用 HTTP 访问时，浏览器对同一主机最多开 6 条左右的连接，标签页开多了就会排队。关掉一些标签页，或者把服务放到支持 HTTP/2 的反向代理后面。

### 文档页是空的

还没有机器同步过这个项目的文档。在仓库里执行 `kh sync`。如果执行过但某些文件没出现：

- 看看 `.kanban-hub/config.yaml` 的 `sync.include` 有没有覆盖到它；
- 看项目设置页的“跳过的文件”，文件可能超过了 `maxFileSize`；
- 指向目录的软链接，以及目标在仓库外的软链接，不会同步。

### HTML demo 打开后提示过期

`/raw` 链接 12 小时有效。回到文档页刷新一下，再点开。

## 文档与隐私

### 私有文档会被传到服务端吗

会，只要它在 `sync.include` 范围内。同步范围不看 `.gitignore`，这是为了让没进 git 的设计文档也能跨机器查看。

注册时自动建议的范围是 `docs/**`、`*.md` 这类，会把 `docs/` 下所有文件都带上。不想上传的文件，写进 `sync.exclude`，或者把 `include` 收窄到具体目录，然后执行一次 `kh sync`。之前已经上传的文件会从服务端的快照里删掉（数据目录的 git 历史里仍然留有记录）。

### kh 会改我的仓库吗

平时只写两个地方：仓库根目录的 `.kanban-hub/`，以及 `.git/info/exclude`（把 `.kanban-hub/` 加进本地排除）。不改 `.gitignore`，不装依赖，不装 git hook，也不改 `CLAUDE.md`、`AGENTS.md` 这类 agent 指令文件。

唯一的例外是拉取文档（`kh pull`，或者会话开始时的自动拉取）：它只写同步范围内、没被 git 跟踪的文件，而且从不删除本地文件。把 `pull.auto` 设为 `false` 可以关掉自动拉取。

## 部署

### 容器起不来，日志说目录不可写

挂载目录的属主和 `PUID`/`PGID` 对不上。日志里会给出要执行的 `chown` 命令。最常见的原因是启动前没有 `mkdir -p data backups`，Docker 以 root 身份自动建了目录。

### 容器起不来，日志说目录不存在

没有挂载 `/data` 或 `/backups`。检查 compose 文件里的 `volumes`。

### 服务端待提交的改动一直不为零

服务端每次写入后安静 30 秒才提交一次 git，平时有几个待提交的文件是正常的。如果数字一直在涨，说明 git 提交失败了，看服务端日志里的错误。数据文件本身已经写好，不会丢。
